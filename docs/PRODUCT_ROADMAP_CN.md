# FabSource 通用采购平台产品路线图

## 当前状态

现在的 FabSource 是一个公开可演示的单场景工具：

- 场景固定为晶圆厂 CVD 干式真空泵；
- 数据存放在浏览器 `localStorage`；
- 不需要登录；
- 不连接 ERP、SRM 或真实供应商；
- 支持 TCO、评分、报价导入、决策包导出和教程。

它适合面试展示和方法验证，但还不能让不同公司的采购员独立维护真实项目。

## 产品目标

把 FabSource 做成一个通用半导体采购决策平台：

> 采购员可以在同一平台创建采购项目、定义技术门槛、收集供应商报价、比较五年 TCO、完成审批，并保留完整证据链。

“通用”不等于所有品类共用一个固定表单，而是让用户能够配置不同品类自己的规格、评分和成本模型。

## 第一优先级：团队可用 MVP

### 1. 账号与团队

- 注册、登录、退出；
- 个人工作区与公司工作区；
- 邀请采购、技术、质量、财务和管理层成员；
- 角色权限：管理员、采购员、技术评审、只读、供应商；
- 所有数据按公司隔离。

### 2. 项目与 RFQ 流程

- 创建采购项目；
- 设置项目负责人、截止日期、预算和采购数量；
- 邀请技术负责人和供应商；
- 状态流转：草稿 → 询价中 → 评审中 → 审批中 → 定标 → 归档；
- 每个项目保留修改历史和审批记录。

### 3. 品类与模板

- 创建品类：干泵、阀门、MFC、石英件、陶瓷件、特气、耗材等；
- 为每个品类维护技术要求模板；
- 技术参数支持数值、文本、布尔值、区间和认证；
- 支持硬门槛、加权项、必填项和单位换算；
- 复制历史项目作为新模板。

### 4. 供应商主数据

- 供应商档案；
- 品牌、工厂、代理、经销商和服务商关系；
- 联系人、区域、认证、服务网络和银行信息；
- 历史报价、交付、质量和异常记录；
- 供应商停用、黑名单和合规状态。

### 5. 报价收集和解析

- 供应商在线填写报价；
- Excel/CSV 批量导入；
- PDF 规格书和报价单解析；
- 币种、汇率、税率、Incoterm 自动归一；
- 缺失字段和异常差异提示；
- 报价版本、澄清记录和附件留存。

### 6. 成本与评分引擎

- 每个品类配置自己的 TCO 公式；
- 自动计算采购、物流、税费、安装、能耗、维护、备件、停机和残值；
- 支持不同评估年限、产量和停机损失；
- 硬门槛与加权评分分离；
- 评分权重可版本化、可审批；
- 每次计算保留完整审计轨迹。

### 7. 审批与审计

- 技术、质量、采购和财务串行或并行审批；
- 支持评论、退回、附件和电子签字记录；
- 记录谁在什么时候修改了参数、报价和权重；
- 所有版本可追溯，不直接覆盖历史版本；
- 导出 PDF 决策包和 XLSX 比选表。

## 第二优先级：真正提高采购效率

### 8. 供应商协同门户

- 供应商只能看到自己的 RFQ；
- 在线提交报价、澄清和文件；
- 报价截止后自动锁定；
- 支持补充报价和商务谈判版本；
- 邮件或企业微信提醒。

### 9. 通知与任务

- 截止日期提醒；
- 待审批提醒；
- 缺少文件提醒；
- 报价异常提醒；
- 交期、质保或认证到期提醒。

### 10. 市场和风险情报

- 供应商新闻、产能公告、财报和专利动态；
- 汇率、关税和出口管制变化；
- 单一来源、区域集中和关键备件风险；
- 自动生成月度品类情报。

### 11. 集成能力

- Excel 和 CSV；
- 企业微信、钉钉、飞书和邮件；
- ERP/SRM 的基础供应商和采购申请同步；
- SSO 单点登录；
- API 和 Webhook。

## 推荐技术架构

### 前端

- 继续使用 Next.js App Router；
- 保留当前桌面工作台和移动端适配；
- 管理端与供应商端分权限展示。

### 后端与数据

- PostgreSQL：项目、用户、供应商、报价、规格、审批和审计；
- Drizzle ORM 或 Prisma：结构化数据访问；
- 对象存储：PDF、Excel、图片和认证文件；
- 后台任务：文件解析、邮件通知、报告生成；
- 定时任务：汇率、到期提醒和情报更新；
- Redis：缓存、队列和短期任务状态。

### 身份与安全

- Auth.js、Clerk 或其他企业级身份服务；
- 企业 SSO/SAML（企业版）；
- 基于角色和项目的权限控制；
- 数据加密、密钥管理、备份和恢复；
- 操作审计与异常登录记录。

### 部署

- 前端与 API：Vercel；
- 数据库：Vercel Marketplace 中的 Neon Postgres 等；
- 文件：Vercel Blob 或兼容 S3 的对象存储；
- 监控：Vercel Observability、Sentry 或同类服务。

## 核心数据模型

## 分阶段实施

### 阶段 0：公开 Demo

- 当前版本已完成；
- 用于展示采购方法、TCO、硬门槛和评分；
- 所有报价明确标记为模拟数据。

### 阶段 1：单公司团队 MVP

目标：一个公司内 3-10 名采购和技术人员可以创建真实项目。

- 登录、团队和权限；
- PostgreSQL 数据持久化；
- 项目、供应商、规格和报价 CRUD；
- 文件上传；
- 审批与版本历史；
- Excel/PDF 导出。

### 阶段 2：多品类采购平台

目标：覆盖设备、零部件、材料和服务类采购。

- 品类模板；
- 自定义 TCO 模型；
- 供应商门户；
- 通知、任务和月度情报；
- 与 Excel、企业微信或邮件集成。

### 阶段 3：企业级平台

目标：适用于多工厂、多法人和复杂合规场景。

- 多组织、多工厂；
- SSO、SAML、细粒度权限；
- ERP/SRM 集成；
- 数据区域与合规；
- 灾备、SLA 和安全审计；
- 供应商绩效与风险评分。

## 上线前必须补齐

- 用户协议、隐私政策和服务条款；
- 数据分类和保留策略；
- 企业采购数据保密与权限审计；
- 供应商资料的使用授权；
- 汇率、价格和公开情报的来源与免责声明；
- 备份恢复演练；
- 错误监控和告警；
- 自动化测试、端到端测试和性能测试；
- 版本发布、回滚和数据库迁移流程。

## 衡量是否“真正好用”的指标

- 创建一次完整 RFQ 所需时间；
- 报价归一所需时间；
- 从报价截止到形成推荐结论所需时间；
- 人工往返修改次数；
- 技术、质量和财务审批周期；
- 报价和规格缺项率；
- 用户在真实项目中主动复用模板的比例；
- 供应商在线提交率；
- 决策包导出和归档完整率。

## 最优建设顺序

1. 登录、团队和数据库；
2. 项目、供应商、规格和报价 CRUD；
3. 审批、版本和审计；
4. 报价导入与文件存储；
5. 多品类模板和自定义成本模型；
6. 供应商门户；
7. 通知和企业集成；
8. 风险情报与企业级能力。

先完成前四项，FabSource 才能从“很完整的 Demo”变成采购员真正愿意在日常工作中使用的产品。
